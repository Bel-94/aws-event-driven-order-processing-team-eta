# OrderPlaced Event Schema

This is the contract between **Order Intake** (publisher) and the Week 2 **consumers** (Payment, Inventory, Notification).

## EventBridge envelope

| Field | Value |
|---|---|
| Event bus | `order-processing-${Environment}` (custom bus) |
| Source | `order.processing` |
| DetailType | `OrderPlaced` |
| Detail | JSON object below (stringified by the SDK as the event `detail`) |

## Detail payload

Matches the DynamoDB order record written by Order Intake (see `infrastructure/valid_order_structure.json`).

```json
{
  "orderId": "ord_8f14e45f-ea3c-4b1a-9d0a-2f6e1c9b7a12",
  "customerId": "cust_3b2a1c9e",
  "items": [
    {
      "sku": "SKU-12345",
      "productName": "Wireless Mouse",
      "quantity": 2,
      "unitPrice": 19.99
    }
  ],
  "status": "PENDING",
  "totalAmount": 39.98,
  "currency": "USD",
  "createdAt": "2026-07-23T14:32:00Z",
  "updatedAt": "2026-07-23T14:32:00Z"
}
```

## Field rules

| Field | Type | Required | Notes |
|---|---|---|---|
| `orderId` | string | yes | Partition key; generated by Order Intake (`ord_` + UUID) |
| `customerId` | string | yes | Non-empty |
| `items` | array | yes | At least one item; each needs `sku`, `quantity`, `unitPrice` |
| `status` | string | yes | Always `PENDING` at publish time |
| `totalAmount` | number | yes | Sum of `quantity * unitPrice` |
| `currency` | string | yes | 3-letter code, default `USD` |
| `createdAt` | string | yes | ISO-8601 |
| `updatedAt` | string | yes | ISO-8601 (same as createdAt at publish) |

Formal JSON Schema: [`schemas/order-placed.schema.json`](schemas/order-placed.schema.json)

## Event pattern (EventBridge rule)

```json
{
  "source": ["order.processing"],
  "detail-type": ["OrderPlaced"]
}
```

## Consumer expectations

Each consumer receives the EventBridge event, reads `event.detail` (already parsed as an object when using the Lambda event source), and updates **its own** status attribute on the same `orderId` (so they do not overwrite each other):

| Consumer | DynamoDB attribute set | Example value |
|---|---|---|
| Payment | `paymentStatus` | `PROCESSED` |
| Inventory | `inventoryStatus` | `RESERVED` |
| Notification | `notificationStatus` | `SENT` |

All consumers also bump `updatedAt`.

## Publish timing

Order Intake flow:

1. Validate request  
2. `PutItem` to DynamoDB (`status: PENDING`)  
3. `PutEvents` → `OrderPlaced` on the custom bus  
4. Return `201` to API Gateway  

If step 3 fails after step 2 succeeded, the Lambda returns `500` and logs clearly — the order row exists but consumers were not notified (acceptable teaching tradeoff for Week 2; outbox/retry is a future improvement).
